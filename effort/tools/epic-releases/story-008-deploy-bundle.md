# A deployment bundle with a manifest, for auto-install

## Summary

Defines the **deployment bundle**: what a tagged build publishes, so
an installer can pick it up and roll it out across a network without
scraping a web page or guessing filenames.

Every release now carries a `manifest.json` alongside the platform
archives, generated by `scripts/make_manifest.py`:

- `schema` — format version, so an installer can refuse one it does
  not understand;
- `version`, `released`, `default_port`;
- per platform: `file`, `sha256`, `size`, and `entry` (what to launch
  once unpacked).

The contract, and the order an installer should do things in, is
documented in README.md under **Deployment bundle** — that section is
the spec; the script is its implementation. The operator is building
the installer side separately against it.

## Definition of Done

- [x] Every tagged release publishes `manifest.json` with the archives.
- [x] It carries a schema version, checksums, sizes and entry points.
- [x] A missing platform is absent rather than wrong, so an installer
      checks for the key.
- [x] The contract is documented for someone writing an installer,
      including the install order and per-platform traps.
- [x] The generator runs and is verifiable locally.

## Out of scope

- The installer itself, and any LAN discovery — the operator is
  building that against this contract.
- Signing or notarisation (still unsigned; the doc says so and tells
  an installer to clear the quarantine flag itself).
